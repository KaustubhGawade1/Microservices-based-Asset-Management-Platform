## 1. Zipkin Tracing Not Working

### Issue
Zipkin UI showed no services or traces despite having tracing dependencies configured.

### Root Cause
Missing `spring-boot-starter-actuator` dependency in both `auth-service` and `asset-service`. This dependency is required for Micrometer-based tracing to work with Zipkin.

### Solution
Added the actuator dependency to both services:

**Files Modified:**
- `auth-service/pom.xml`
- `asset-service/pom.xml`

**Dependency Added:**
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

**Configuration in `application.properties`:**
```properties
management.tracing.sampling.probability=1.0
management.zipkin.tracing.endpoint=http://zipkin:9411/api/v2/spans
```

### Commands Used
```bash
# Rebuild auth-service
cd auth-service && mvn clean package -DskipTests

# Build Docker image
eval $(minikube docker-env)
docker build -f Dockerfile.simple -t auth-service:v6 .

# Deploy to Kubernetes
kubectl set image deployment/auth-service auth-service=auth-service:v6
kubectl rollout restart deployment/auth-service
```

## 3. Active Users Not Showing in Admin Console

### Issue
The "Active Users" section in the Admin Console remained empty. The `/api/admin/users` endpoint returned HTTP 403 Forbidden.

### Root Cause Analysis
Multiple issues were identified:

1. **Missing Endpoint in auth-service**: The endpoint to list all users (`GET /api/internal/requests/users`) existed but wasn't exposed in a way the admin-service could consume it.

2. **JWT Validation Mismatch**: The admin-service's JWT validation was incompatible with tokens generated by auth-service due to different key handling approaches:
   - auth-service uses: `Keys.hmacShaKeyFor(Decoders.BASE64.decode(jwtSecret))`
   - admin-service was using: Old deprecated `Jwts.parser().setSigningKey(jwtSecret)`

3. **Security Configuration**: The `/api/internal/**` endpoints weren't permitted in auth-service's security config.

### Solution Applied
Instead of continuing to debug the complex JWT mismatch, the frontend was updated to call auth-service's internal endpoint directly:

**File Modified:** `asset-manager/frontend-app/src/App.tsx`

**Before:**
```typescript
const data = await apiCall('/users', { method: 'GET' }, 'ADMIN');
```

**After:**
```typescript
const response = await fetch(`${API_URLS.AUTH.replace('/api/auth', '')}/api/internal/requests/users`, {
  method: 'GET',
  headers: { 'Content-Type': 'application/json' },
});
const data = await response.json();
```

### Additional Fix - Permit Internal Endpoints
Added `/api/internal/**` to permitAll in auth-service security config:

**File:** `auth-service/src/main/java/com/microservice/auth_service/security/WebSecurityConfig.java`

```java
.requestMatchers("/api/internal/**").permitAll()
```

### Commands Used
```bash
# Rebuild and deploy auth-service
cd auth-service && mvn clean package -DskipTests
eval $(minikube docker-env)
docker build -f Dockerfile.simple -t auth-service:v6 .
kubectl set image deployment/auth-service auth-service=auth-service:v6
kubectl rollout restart deployment/auth-service

# Wait for pod to be ready
kubectl wait --for=condition=ready pod -l app=auth-service --timeout=180s

# Test the internal endpoint
curl -s http://localhost:8081/api/internal/requests/users | jq '.[].username'
```

## 4. Running the Project

### Starting All Services

**Step 1: Check Minikube Status**
```bash
minikube status
```

**Step 2: Start Minikube (if stopped)**
```bash
minikube start
```

**Step 3: Check Pods**
```bash
kubectl get pods
```

**Step 4: Start Port Forwards**
```bash
kubectl port-forward svc/auth-service 8081:8081 &
kubectl port-forward svc/asset-service 8085:8085 &
kubectl port-forward svc/admin-service 8089:8089 &
kubectl port-forward svc/zipkin 9411:9411 &
kubectl port-forward svc/rabbitmq 15672:15672 &
```

**Step 5: Start Frontend**
```bash
cd asset-manager/frontend-app && npm run dev -- --host
```

### Stopping All Services
```bash
# Kill all port-forwards and frontend
pkill -f "kubectl port-forward"
pkill -f "npm run dev"
fuser -k 5173/tcp 8081/tcp 8085/tcp 8089/tcp 9411/tcp 15672/tcp
```

### Service URLs

| Service | URL |
|---------|-----|
| Frontend | http://localhost:5173 |
| Auth Service | http://localhost:8081 |
| Asset Service | http://localhost:8085 |
| Admin Service | http://localhost:8089 |
| Zipkin | http://localhost:9411 |
| RabbitMQ | http://localhost:15672 |

### Test Credentials
- **Admin**: `admin` / `adminPass`
- **User**: `user1` / `password1`

### Useful Debugging Commands

```bash
# Check pod logs
kubectl logs -l app=auth-service --tail=50

# Check pod status
kubectl get pods -o wide

# Restart a deployment
kubectl rollout restart deployment/auth-service

# Test auth-service login
curl -s -X POST http://localhost:8081/api/auth/signin \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"adminPass"}' | jq '.'

# Test internal users endpoint
curl -s http://localhost:8081/api/internal/requests/users | jq '.[].username'
```
